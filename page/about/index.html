AI Engineer · 비지도 이상탐지 · 모델 서빙 · 데이터 파이프라인

24, 2026

유태욱

비지도 이상탐지 모델을 만들고, 그 모델이 고객의 운영 환경에서 돌아가게 하는 데까지 맡아 온 AI 엔지니어입니다.

공정 이미지와 설비 센서 시계열을 대상으로 비지도 이상탐지 모델을 개발했고, 모델을 ONNX·Triton으로 서빙해 온프레미스·폐쇄망 서버에 올렸습니다. 지금은 수집부터 추론 요청까지 이어지는 범용 데이터 파이프라인 플랫폼을 만들고 있습니다.

경험에서 얻은 것

비전 이상탐지 — 연구 인턴 (2023.10 ~ 12)

원단 이미지 85,570장으로 비지도 이상탐지 모델을 개발했습니다.

  • GAN·VAE·Diffusion·Normalizing Flow 계열을 같은 데이터로 비교해 모델을 고르는 법 (MSFlow, Det AUROC 99.87)
  • 개선안을 미리 정하지 않고 측정 결과로 방향을 정하는 법: pruning을 측정 결과로 기각하고 배치 구성을 바꿔 처리량 24 → 157 fps

시계열 이상탐지와 모델 서빙 — 철도차량 CBM (2024.08 ~ 2026.01)

고장 데이터가 거의 없는 설비 센서 데이터로 장치별 모델을 만들어 5종 장치에 운영 배포했습니다.

  • 정상을 정의하는 모델링: 성능을 좌우한 것은 모델 구조보다 학습 데이터의 분포와 스케일링 기준이었고, 이상 점수 왜곡의 원인을 데이터 범위에서 찾았습니다.
  • 서빙 가능한 형태로 만들기: 구성이 바뀌는 여러 OneClassSVM을 고정 입출력의 ONNX 그래프 하나로 병합해 Triton으로 서빙했습니다 (11개 → 1개).
  • 폐쇄망 현장 적용: 외부망이 없는 고객사 서버에 학습 모듈과 추론 모델을 직접 설치했고, 반입 절차와 CLI 분석 도구를 준비했습니다.

범용 데이터 파이프라인 플랫폼 — 사내 (2025.04 ~)

수집 → 적재 → 스케줄링 → 전처리 → 추론 요청까지, 처리 모듈 17종을 개발했습니다.

  • 구조로 보장하는 설계: 비동기 체인의 교착을 재시도 대신 큐 직렬성으로 해결했고, 같은 패턴을 모듈 13종에 적용했습니다.
  • 검증 설계: 옮긴 전처리를 기존 시스템과 2트랙으로 전수 대조했습니다 (642/642). 이 과정에서 재구현 결함 2건을 찾아 수정했습니다.
  • 배포를 전제로 한 구성: 설정 profile 분리, 디렉토리 단위 반입, 주소 재지정 스크립트로 온프레미스 서버 이전을 단순화했습니다.

일하는 방식

  • 문제가 생기면 모델보다 데이터가 어떻게 만들어졌는지를 먼저 봅니다.
  • 판단은 측정으로 하고, 맞다는 것은 대조로 증명합니다.
  • 구현은 AI 코딩 에이전트에 맡기되, 무엇이 맞는 결과인지는 직접 정합니다. (Claude Code + 작업 규칙 문서·훅·검증 커맨드)
