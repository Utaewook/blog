  • 결과 sleep·재시도 없이 해소했다.

B-1. 이상 점수 왜곡의 원인은 모델이 아니라 데이터 범위였다

정상을 정의하는 모델링 견인전동기 · TranAD · 2024.11 ~ 2025.08

58℃ / 83℃3개 조건100℃ 이상
학습셋 / 검증셋 베어링 온도 최대값추가한 센서 오류 필터 (과속·0값·상수 구간)외기 5℃ 운행 중 재설계 모델이 잡은 코일 온도
  • 문제 정상 구간인데 이상 점수가 높게 나왔다.
  • 원인 스케일링 범위를 벗어난 온도 입력이 재구축 출력 전체를 흔들어, 무관한 속도 피처 점수까지 올렸다.
  • 판단 최대·최소 범위를 포함하도록 데이터셋을 다시 구성했다. 속도 피처를 뺀 모델은 개선이 없어 기각했다.
  • 결과 재설계한 운영 모델이 열화 의심 사례와 센서 이상을 구분해 잡아냈다.

B-2. 모델 4종을 비교한 끝에 기존 TranAD를 깊게 팠다

정상을 정의하는 모델링 차축베어링 · TranAD · 2025.10 ~ 11

4종4분할1.2 / 1.0 / 0
같은 데이터셋으로 비교한 모델 (AutoEncoder·VAE·DAGMM·TranAD)고장 주파수별 내부 모델재구축 loss 가중치 (고장 주파수 / 공통 / 속도)
  • 문제 진동 기반 통계 특징이 많아 새 모델이 필요해 보였다.
  • 원인 피처별 재구축 오차를 분해하니, 고장 주파수 대역과 일부 진동 피처만 복원하지 못하고 있었다.
  • 판단 AutoEncoder·VAE·DAGMM은 TranAD보다 못해 채택하지 않았다. 대신 고장 주파수별로 모델을 나누고 loss 가중치를 다르게 줬다.
  • 결과 window·샘플링 조합(window 10, 30초)을 골랐고, 가상 열화 데이터로 반응을 확인한 뒤 배포했다.

B-3. 여러 개의 SVM을 ONNX 그래프 하나로

서빙 가능한 형태로 만들기 다중 OneClassSVM · skl2onnx · Triton · 2025.05 ~ 06

11개 → 1개3종4.77e-07
주공기압축기 기준, 하위 SVM을 단일 ONNX 그래프로 병합같은 변환 구조를 적용한 장치변환 후 발견한 부동소수점 오차 크기
  • 문제 장치 단위로 설계된 서비스 위에서, 장치 정책마다 그룹 구성이 다른 다중 SVM을 장치당 모델 하나로 서빙해야 했다. 출력도 label이 아니라 decision score여야 했다.
  • 원인 기본 변환은 label만 내보내고, 다중 구조의 입력 분리가 그래프에 연결되지 않았다.
  • 판단 기본 변환과 SvmRegressor 노드 매핑을 거쳐, 커스텀 컨버터로 입력 분기까지 그래프 안에 넣었다.
  • 결과 그룹 수와 관계없이 입력 1개·출력 1개로 고정돼, 장치 단위 구조와 Triton 설정을 그대로 쓸 수 있었다. 변환 전후 출력 차이는 정밀도 문제로 정리했다.

폐쇄망 현장 적용 · 운영 배포 이후

폐쇄망 현장 적용

  • 학습·수집·추론·DB 서버가 나뉜 고객사 온프레미스 환경에 학습 모듈과 추론 모델을 패키지 단위로 직접 설치하고 확인했다.
  • 외부망이 없어 USB·SCP로 반입했다. 절차는 출력용 문서로 정리했고, 분석 도구는 CLI(csv·pdf 출력)로 만들었다.
  • 데이터 반출용 분할 압축·체크섬 절차를 정리했고, 반출한 데이터로 사내에서 추론·열화 결과를 다시 분석했다.
  • 5종 배포 후 오탐 분석
    • 공조장치: 모델 입력과 방향성 판단 기준이 달라 “방향성은 정상인데 점수가 높은” 구조적 원인을 찾았다.
    • 승강문: 0mA 동작 구간의 오추론을 확인했다.
    • 차축베어링: 센서 이상과 실제 진동 상승을 구분했다.
