백엔드 분야 학습을 위해 기본적인 웹에 관련된 내용을 한번 알아보았다. 웹 페이지는 HTTP의 요청과 응답을 통해 서버로부터 가져와지는데, 이를 더 자세히 알아보자.

1. HTTP 요청

HTTP 요청 메시지는 시작줄(Start Line), 헤더(Header), 그리고 선택적인 본문(Body)으로 크게 세 부분으로 구성된다.

  1. 시작 줄(Start Line)
    • 요청 메소드 (Method): 메소드는 클라이언트가 수행하고자 하는 동작을 나타낸다. 예를 들어, ‘GET’, ‘POST’, ‘PUT’, ‘DELETE’등이 있다.
    • 요청 URI(타겟): 클라이언트가 요청하는 리소스의 주소이다. 주로 URL 또는 프로토콜, 포트, 도메인의 절대경로로 이루어져 있다. /index.html, /index/logo.png와 같은 예시가 있다.
    • HTTP 버전: 클라이언트가 사용하는 HTTP 프로토콜의 버전이다. (HTTP/1.1, HTTP/2 등)
  2. 헤더(Headers)
    • 일반 헤더(General Headers): 요청과 응답 모두에 공통적으로 적용되는 헤더들이 있다. (Cache-control, Date 등)
    • 요청 헤더(Reqeust Headers): 요청에 대한 추가 정보를 제공한다. 요청이 전송되는 대상 서버를 나타내는 Host, 클라이언트의 브라우저 정보를 나타내는 User-Agent, 클라이언트가 받을 수 있는 콘텐츠 유형을 나타내는 Accept 헤더 등이 있다.
    • 엔티티 헤더(Entity Headers) 혹은 Representation Headers: 요청이 본문에 포함된 데이터에 대한 정보를 나타낸다. (Content-Type, Content-Length 등)
  3. 본문(Body)
    • 이는 선택 사항으로 ‘POST’나 ‘PUT’ 요청에서 주로 사용되며 서버로 전송되는 데이터를 포함한다. HTML 폼 데이터, JSON 객체 등이 될 수 있다.

2. HTTP 응답

HTTP 응답 메시지 역시 세 부분으로 구성된다. 상태 줄(Status Line), 헤더(Headers), 본문(Body)로 구성!

  1. 상태 줄 (Status Line)
    • HTTP 버전: 응답에 사용된 HTTP 프로토콜의 버전을 나타낸다. (보통 HTTP/1.1이라고 한다..?  -> 2022년 기준 HTTP/2가 대부분)
    • 상태 코드(Status Code):요청 처리 결과를 나타내는 숫자 코드이다. 200(OK), 404(Not Found)등이 대표적이다.
    • 상태 텍스트(Reason Phrase): 상태코드의 간단한 설명이다. OK, Not Found와 같은 텍스트를 의미
  2. 헤더(Headers)
    • 응답 헤더(Response Headers):응답에 대한 추가적인 정보를 제공한다. Server(서버 소프트웨어 정보), Content-Type(응답의 MIME 유형) 등이 있다.
    • 일반 헤더 및 엔티티 헤더: 응답에도 요청과 같이 일반 헤더와 엔티티 헤더가 포함될 수 있다.
  3. 본문(Body)
    • 마찬가지로 실제로 요청된 리소스의 내용이 포함된다. HTML문서, 이미지 파일, JSON 데이터 등이 될 수 있다.

MIME Type이 뭐지?

MIME이란 Multipurpose Internet Mail Extension의 약자로, 인터넷에서 파일의 형식을 나타내는 표준 방식이라고 한다. 원래는 이메일에서 다양한 종류의 파일(이미지, 텍스트, 오디오, 비디오 등등)을 전송하기 위해서 개발되었는데, 웹에서도 쓰이게 되었다고!

구조

MIME 유형은 일반적으로 “타입/서브타입” 형식으로 표현된다. 예를 들어서

  • text/html: HTML 문서
  • image/jpeg: JPEG 이미지 파일
  • application/json: JSON 형식의 데이터

MIME 유형은 웹 통신에서 데이터를 정확하고 안전하게 전송하는 데 필수적인 역할을 하며, MIME 유형을 올바르게 설정하고 관리하는 것이 중요하다고 한다!

3. 예시!

HTTP 메시지의 예시를 보고 분석해 보면서 요청과 응답의 내용을 유추해 보자!

HTTP 요청 메시지의 예시는 아래와 같다.

GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/58.0.3029.110 Safari/537.36
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8

위의 요청을 분석해 보면 다음과 같다.

  • 시작 줄: 요청 대상인 /index.html을 GET 메소드로 받아온다는 요청을 의미한다. 또한 클라이언트가 사용하는 HTTP 프로토콜의 버전이 1.1 임을 알 수 있다.
  • 헤더: Host 헤더에서 요청이 전송되는 대상 서버의 이름이 ‘www.example.com’임을 알 수 있으며, User-Agent 태그의 내용을 통해  클라이언트의 브라우저 정보를 알 수 있다. 또한 Accept 헤더를 통해 클라이언트가 처리할 수 있는 콘텐츠 유형을 나타내며 여기서는 HTML, XHTML, XML, 이미지 등 다양한 유형의 콘텐츠를 받을 수 있음을 나타낸다.
  • Body 부분은 따로 없다. 헤더 이후 공백 line이 한 줄 있고 난 다음, 내용이 들어온다!

다음으로 HTTP 응답 메시지의 예시는 아래와 같다.

HTTP/1.1 200 OK
Date: Mon, 23 May 2022 22:38:34 GMT
Server: Apache/2.4.1 (Unix)
Content-Type: text/html; charset=UTF-8
Content-Length: 155

<!DOCTYPE html>
<html>
<head>
    <title>Example Page</title>
</head>
<body>
    <p>Hello, World!</p>
</body>
</html>
  • 상태 줄: 응답에 사용된 HTTP 프로토콜의 버전이 1.1 임을 알 수 있으며, ‘200 OK’를 통해 요청이 성공적으로 처리되었음을 알 수 있다.
  • 헤더: Date 헤더에서 응답이 생성된 날짜와 시간, Server 헤더에서 응답을 보내는 서버의 소프트웨어가 Apache 버전 2.4.1, Content-type 헤더에서 응답 본문의 MIME 타입(text/html이고, 문자 인코딩은 UTF-8), Content-length 헤더에서 본문의 길이를 알 수 있다.
  • 본문: Body 부분에는 실제로 서버가 전송한 HTML문서의 내용이 포함되어 간단한 웹페이지를 전송하였다. 페이지 제목과 ‘Hello, World!‘라는 텍스트가 웹 페이지에 표시된다.

mozilla의 개발자를 위한 웹 기술이라는 문서에 많은 내용이 나와있었다. 이것과 실제 예시의 분석을 통해 HTTP 요청과 응답 메시지에 관해 알아보았다.
